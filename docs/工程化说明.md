# 金属垫片视觉分拣系统

## 1. 系统边界

系统面向中低速五金产线，识别金属垫片的缺口与变形并完成自动剔除。

```text
光电传感器
    │
    ▼
STM32F103C6T6 ── 触发帧(seq) ──► Jetson Nano + USB相机
    │                              │ TensorRT FP16推理
    │◄─ 结果帧(seq/result/conf) ───┘
    │── ACK(seq) ─────────────────►
    ├── TB6600 / 步进电机：传送带启停
    └── 电磁阀 / 气缸：缺陷件剔除
```

STM32 是产线节拍和安全策略的主控；Jetson 只负责视觉推理。视觉服务失联、相机无新帧、结果帧损坏或结果超时均执行失效安全剔除，避免未检测工件静默放行。

## 2. 已落地的工程化改造

### STM32 / FreeRTOS

- 固定为检测、通信、执行 3 个静态任务，优先级依次为执行 `High`、通信 `AboveNormal`、检测 `Normal`。
- 使用 3 个静态二值信号量同步“传感器触发—通信事务—执行完成”，任务、信号量及内核 Idle/Timer 任务均静态分配，并关闭动态内存。
- 通信事务预算固定为 185 ms：首帧发送 80 ms 未响应时重发一次，为 5 ms 传感器去抖和 RTOS 调度预留约 10 ms 裕量，以满足 195 ms 端到端目标。
- 结果码区分正常、缺口、变形和视觉异常；通信/视觉异常统一执行失效安全剔除。
- 增加栈溢出 Hook；对象创建失败或运行时栈异常均停止传送带并关闭气缸输出。
- PWM Compare 根据 ARR 自动计算为 50%，避免 CubeMX 修改 Period 后出现 `Compare > ARR` 导致无脉冲；PWM 启动失败进入错误处理。
- UART 从 9,600 bit/s 提升到 115,200 bit/s，8 字节单帧线速时间约 0.69 ms。- 独立看门狗(IWDG,LSI /256,超时约 1 s)与最高优先级 Monitor 任务:检测/通信/执行三任务每轮迭代自增心跳计数,Monitor 每 100 ms 比对,任一任务停摆超过 5 个周期(500 ms)即停止喂狗触发硬件复位;看门狗在调度器启动前、PWM 启动成功后开启。
- 双向心跳与视觉失联快速剔除:STM32 空闲时每秒发送 `HEARTBEAT`,Jetson 回复 ACK;Jetson 每秒发送携带串口 RX 校验错误计数的 `HEARTBEAT`,STM32 回复 ACK 并刷新链路存活时间戳;连续 3 s 无任何有效帧即判定视觉失联,该工件不再等待 400 ms 事务预算,直接按失效安全立即剔除(计入 `vision_lost_rejects`)。
### Jetson Nano

- TensorRT 引擎启动时预热，将 CUDA 首次分配移出在线时延路径。
- 独立相机线程持续清空 UVC 缓冲，只保留最新帧；超过 200 ms 的旧帧不参与判定。
- 自定义模型类别约定为 `notch`、`deformation`，输出明确的缺陷类型和 0–100 置信度。
- 以 8 位事务序号缓存最近结果：同一触发帧重发时直接回放结果，不重复推理；收到 STM32 ACK 后删除缓存。
- 队列有界，串口解析可在噪声或半帧后重新同步；运行日志采用 JSON Lines，记录序号、类别、置信度、Jetson 收到触发帧至发出结果帧的服务时延及是否超出 195 ms。
- 提供 systemd 单元与环境变量配置，支持开机启动和进程异常自动拉起。- 相机线程连续读帧失败(约 0.6 s)自动释放并重开 USB 相机,重开次数入 metrics 并输出 `camera_reopen` 事件,拔插后无需重启服务。
- 缺口/变形/视觉异常帧经有界队列由后台线程 JPEG 落盘(文件名含时间戳、事务序号与结果码),不占用推理时延路径;队列溢出计数并告警。路径与开关由环境变量控制。
### 双向 UART 协议

固定帧长 8 字节：

| 字段 | SOF1 | SOF2 | VER | TYPE | SEQ | CODE | AUX | XOR |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 长度/B | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
| 取值 | `AA` | `55` | `01` | 消息类型 | 事务序号 | 结果/参数 | 置信度 | `VER..AUX` 异或 |

消息类型：`0x10 TRIGGER`、`0x20 RESULT`、`0x30 ACK`、`0x40 HEARTBEAT`。序号、超时重发、重复结果缓存和 ACK 共同保证事务幂等；XOR 用于检测单比特及常见突发错误。若要用于强干扰长距离链路，应把物理层改为隔离 RS-485，并将 XOR 升级为 CRC-16。心跳帧的 AUX 字段携带串口 RX 校验错误计数，用于在线链路质量观测。

## 4. 上线前必须补齐的验证

仓库不包含垫片数据集、训练权重或 TensorRT engine，因此不能从当前代码推导检测准确率。上线前至少需要：

1. 固定光源、曝光、相机高度和 ROI，准备覆盖材质反光、旋转角度、轻微/严重缺陷的独立测试集。
2. 分别统计缺口、变形的 Precision、Recall、F1，并单独关注漏检率；阈值必须由验证集确定，不能只使用默认的 0.45。
3. 连续运行不少于 2 小时，记录触发至结果的 P50/P95/P99、超时率、重发率和误剔率。
4. 用逻辑分析仪同时采集光电输入、UART 和气缸输出。简历中的“≤195 ms”应明确为“光电触发到 STM32 收到有效结果/形成决策”，不包含 120 ms 气缸保持时间。
5. 注入断线、错校验、相机拔出、Jetson 进程退出和重复触发，确认均不会让未检测工件放行。

## 5. 运行方式

Jetson 环境变量示例见 `deploy/washer-inspection.env.example`。将工程与模型部署到 `/opt/washer-inspection` 后安装 systemd 单元：

```bash
sudo cp deploy/washer-inspection.service /etc/systemd/system/
sudo cp deploy/washer-inspection.env.example /etc/washer-inspection.env
sudo systemctl daemon-reload
sudo systemctl enable --now washer-inspection
journalctl -u washer-inspection -f
```

协议测试：

```bash
python3 -m unittest discover -s tests -v
```

## 6. 下一步规划（真工业线方向，尚未落地）

当前版本已覆盖单机可靠运行与失效安全，以下能力面向真实产线部署时再补齐：

1. **剔除闭环验证** — 在剔除位加磁性开关或下游光电传感器，确认工件确实被剔除；动作失败立即告警停机，消除“开环剔除”盲区。
2. **参数持久化** — 用 Flash 仿真 EEPROM 保存剔除延迟、节拍、超时阈值等运行参数，支持经协议远程读写，现场调参无需重新烧录固件。
3. **链路升级** — 物理层改为隔离 RS-485 并将 XOR 升级为 CRC-16（心跳 AUX 已预留链路质量上报字段）。
4. **故障现场记录** — HardFault 上下文（PC/LR/CFSR）写入备份 SRAM，复位后经诊断帧上报；增加上电自检（POST）与光电传感器常亮/常灭自诊断。
5. **生产数据上抛** — 合格/剔除/超时计数与缺陷图像经 MQTT 或 OPC UA 上抛产线管理系统（MES），支持批次追溯。
